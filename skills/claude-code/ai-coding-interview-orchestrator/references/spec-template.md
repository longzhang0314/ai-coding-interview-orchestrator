```markdown
- 可以通过命令运行：

- 有最小测试或验证脚本：
```

## Writing Rules

- Do not turn the spec into a long product document.
- Make assumptions explicit instead of blocking on unclear wording.
- Prefer names that can map directly to files/classes/functions.
- Keep acceptance criteria executable whenever possible.
